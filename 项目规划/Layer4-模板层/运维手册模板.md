## 二、日常运维操作

### 2.1 查看服务状态

```bash
# 查看所有容器状态（绿色 Up 为正常）
docker-compose -f /opt/myapp/docker-compose.prod.yml ps

# 预期正常输出：
# NAME          IMAGE         STATUS         PORTS
# myapp-nginx   nginx:alpine  Up 3 days      0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp
# myapp-backend myapp:v1.2.0  Up 3 days      8080/tcp
# myapp-db      postgres:16   Up 3 days      5432/tcp
# myapp-redis   redis:7       Up 3 days      6379/tcp

# 快速健康检查（返回 200 表示正常）
curl -s -o /dev/null -w "%{http_code}" https://yourdomain.com/api/v1/health
```

### 2.2 查看日志

```bash
# 进入项目目录
cd /opt/myapp

# 查看后端实时日志
docker-compose -f docker-compose.prod.yml logs -f backend

# 查看最近 100 行日志
docker-compose -f docker-compose.prod.yml logs --tail=100 backend

# 查看 Nginx 访问日志
docker-compose -f docker-compose.prod.yml logs --tail=100 nginx

# 查看数据库日志
docker-compose -f docker-compose.prod.yml logs --tail=50 db

# 查看所有服务日志（不推荐，输出太多）
docker-compose -f docker-compose.prod.yml logs --tail=50

# 过滤错误日志（ERROR 级别）
docker-compose -f docker-compose.prod.yml logs backend | grep '"level":"error"'
```

### 2.3 重启服务

```bash
# 重启后端（不影响数据库，推荐用于更新配置）
docker-compose -f docker-compose.prod.yml restart backend

# 重启 Nginx（用于 Nginx 配置变更后）
docker-compose -f docker-compose.prod.yml restart nginx

# 重启所有服务（慎用，会有短暂不可用）
docker-compose -f docker-compose.prod.yml restart

# ⚠️ 注意：restart 不会重新拉取新镜像，仅重启现有容器
```

### 2.4 更新前端（不停机）

```bash
# 1. 将新的前端构建产物上传到服务器
scp -r ./frontend/dist/* deploy@[服务器IP]:/var/www/frontend/dist/

# 2. 重新加载 Nginx（不中断现有连接）
docker-compose -f docker-compose.prod.yml exec nginx nginx -s reload
# 或：
docker-compose -f docker-compose.prod.yml restart nginx
```

### 2.5 检查磁盘空间

```bash
# 查看磁盘使用情况
df -h

# 查看 Docker 占用
docker system df

# 清理 Docker 垃圾（旧镜像、停止的容器、未使用的网络）
# ⚠️ 谨慎：会删除未使用的数据
docker system prune -f
```

## 三、部署新版本

### 3.1 标准发版流程

```bash
cd /opt/myapp

# Step 1：备份数据库（发版前必做）
make db-backup

# Step 2：拉取最新代码
git pull origin main

# Step 3：查看将要部署的版本变更
git log --oneline HEAD~5..HEAD

# Step 4：构建新镜像
docker-compose -f docker-compose.prod.yml build backend

# Step 5：执行数据库迁移（如有）
docker-compose -f docker-compose.prod.yml run --rm backend make migrate

# Step 6：滚动重启后端（零停机，需要健康检查配置）
docker-compose -f docker-compose.prod.yml up -d backend

# Step 7：验证新版本
curl -s https://yourdomain.com/api/v1/health | jq .
docker-compose -f docker-compose.prod.yml logs --tail=20 backend
```

### 3.2 紧急回滚流程

```bash
# 代码回滚到上一个版本
cd /opt/myapp
git log --oneline -5       # 查看最近提交
git revert HEAD --no-edit  # 生成回滚提交
git push origin main       # 推送后 CI/CD 自动触发重新部署

# 或者：手动回滚到指定版本
git checkout <commit-hash>
docker-compose -f docker-compose.prod.yml build backend
docker-compose -f docker-compose.prod.yml up -d backend

# 数据库回滚（仅在 Migration 引起问题时使用，谨慎操作！）
docker-compose -f docker-compose.prod.yml run --rm backend make migrate-down
# ⚠️ 数据库回滚可能导致数据丢失，执行前必须确认已备份！
```

## 四、数据库运维

### 4.1 日常备份

```bash
# 手动备份（备份文件包含日期时间戳）
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
docker-compose -f /opt/myapp/docker-compose.prod.yml exec db \
  pg_dump -U [DB_USER] [DB_NAME] > /backup/myapp_${TIMESTAMP}.sql

echo "备份完成：/backup/myapp_${TIMESTAMP}.sql"
ls -lh /backup/myapp_${TIMESTAMP}.sql

# 推荐：设置每日自动备份（crontab）
# crontab -e 添加以下内容
# 0 3 * * * /opt/myapp/scripts/backup.sh >> /var/log/backup.log 2>&1
```

### 4.2 恢复数据库

```bash
# ⚠️ 恢复操作会覆盖现有数据，谨慎！

# Step 1：停止后端服务（防止数据继续写入）
docker-compose -f /opt/myapp/docker-compose.prod.yml stop backend

# Step 2：恢复数据库（选择对应的备份文件）
docker-compose -f /opt/myapp/docker-compose.prod.yml exec -T db \
  psql -U [DB_USER] [DB_NAME] < /backup/myapp_20260413_030000.sql

# Step 3：重启后端
docker-compose -f /opt/myapp/docker-compose.prod.yml start backend

# Step 4：验证数据
curl https://yourdomain.com/api/v1/health
```

### 4.3 连接数据库（查询/排障）

```bash
# 进入 PostgreSQL 控制台
docker-compose -f /opt/myapp/docker-compose.prod.yml exec db \
  psql -U [DB_USER] -d [DB_NAME]

# 常用 SQL
# \dt               -- 查看所有表
# \d users          -- 查看 users 表结构
# SELECT COUNT(*) FROM users WHERE deleted_at IS NULL;  -- 查询有效用户数
# SELECT * FROM users ORDER BY created_at DESC LIMIT 10; -- 最近注册用户

# 退出
# \q
```

## 五、常见问题处理

### 5.1 故障排查速查表

| 症状 | 可能原因 | 排查步骤 |
|---|---|---|
| 网站完全无法访问 | Nginx 未运行 / 服务器 IP 被封 | 1. `ping yourdomain.com` 2. SSH 到服务器检查 Nginx 状态 3. 查看云服务商安全组规则 |
| API 全部返回 500 | 后端崩溃 / 数据库连接断开 | 1. `docker ps` 查看容器状态 2. `docker logs` 查看后端日志 3. 检查数据库容器 |
| 登录返回 401（密码正确） | JWT Secret 配置错误 / Token 过期策略问题 | 1. 检查环境变量 JWT_SECRET 是否正确 2. 检查 Redis 是否正常运行 |
| 页面空白 / 404 | 前端构建失败 / Nginx 配置错误 | 1. 检查 /var/www/frontend/dist 是否有文件 2. 查看 Nginx 错误日志 |
| 接口响应很慢 | 数据库慢查询 / 缺少索引 / 连接池满 | 1. 查看后端日志中的慢请求 2. PostgreSQL 慢查询日志 3. 检查连接池配置 |
| 磁盘空间不足 | 日志文件过大 / Docker 镜像积累 | 1. `df -h` 查看 2. `docker system df` 3. 清理旧日志和镜像 |
| SSL 证书过期 | Let's Encrypt 自动续期失败 | 1. `certbot renew --dry-run` 测试 2. 手动执行 `certbot renew` |

### 5.2 后端服务崩溃处理

```bash
# Step 1：查看崩溃原因
docker-compose -f docker-compose.prod.yml logs --tail=100 backend | grep -E "error|panic|fatal"

# Step 2：尝试重启
docker-compose -f docker-compose.prod.yml restart backend

# Step 3：如果重启后仍崩溃，回滚到上一个版本
git log --oneline -5
git revert HEAD --no-edit && git push origin main

# Step 4：联系开发者（提供完整日志）
docker-compose -f docker-compose.prod.yml logs --since=1h backend > /tmp/error_$(date +%Y%m%d%H%M).log
```

### 5.3 数据库连接超时

```bash
# 检查数据库容器状态
docker-compose -f docker-compose.prod.yml ps db
docker-compose -f docker-compose.prod.yml logs db

# 检查连接数
docker-compose -f docker-compose.prod.yml exec db \
  psql -U [DB_USER] -c "SELECT count(*) FROM pg_stat_activity;"

# 重启数据库（会导致所有连接断开，后端服务会自动重连）
docker-compose -f docker-compose.prod.yml restart db
```

## 七、SSL 证书管理

```bash
# 查看证书有效期
sudo certbot certificates

# 手动续期（Let's Encrypt 证书 90 天有效，建议 60 天时续期）
sudo certbot renew

# 自动续期（已配置 crontab，每月 1 日和 15 日运行）
# 查看 crontab：
sudo crontab -l | grep certbot

# 续期后重新加载 Nginx
docker-compose -f /opt/myapp/docker-compose.prod.yml restart nginx
```
