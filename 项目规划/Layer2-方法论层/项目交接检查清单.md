# 项目交接检查清单

> **文档定位**：Layer 2 — 方法论层（用于项目收尾和客户交付）
> **核心原则**：交接不仅是代码移交，更是信任的建立。完整的交接包能体现工程师的专业素养。
> **适用时机**：项目上线验收前 1 周开始准备

---

## 一、交接总览

```
交接阶段时间线（建议）：

M4 上线前 1 周  ──▶  准备交接文档包
                      - README.md
                      - API 文档
                      - 数据库设计文档
                      - 部署运维手册

M4 生产上线日   ──▶  协助客户验收
                      - 功能演示
                      - 验收清单签字

M4+3 天        ──▶  交接沟通
                      - 运维培训（1-2 小时视频会议）
                      - 账号密码安全移交
                      - 遗留问题说明

M4+7 天        ──▶  正式交接完成
                      - 签收交接确认单
                      - 质保期开始（建议 1-3 个月）
```

## 二、交接文档清单

### 2.1 必须交付的文件

```markdown
## 项目交接包（Handover Package）

### 📄 核心文档
- [ ] README.md（项目概述、本地启动指南、常用命令）
- [ ] API 文档（Swagger/OpenAPI，可交互版本，地址：https://xxx/swagger）
- [ ] 数据库设计文档（表结构、索引说明、关键字段注释）
- [ ] 部署运维手册（如何重启服务、查看日志、执行回滚）
- [ ] 环境变量清单（所有配置项说明，不含具体值，使用 .env.example）

### 🔑 账号与密钥（通过加密方式交接，禁止明文邮件发送）
- [ ] 服务器访问信息（IP、SSH 密钥、登录用户名）
- [ ] 数据库账号（主机、端口、用户名、密码）
- [ ] Redis 访问信息
- [ ] 第三方服务账号（微信支付 AppID/密钥、短信服务、OSS等）
- [ ] 域名注册商账号（如已帮客户购买域名）
- [ ] SSL 证书（证书文件 + 私钥，或 Let's Encrypt 自动续期配置说明）
- [ ] GitHub/GitLab 仓库访问权限（邀请客户为 Owner）

### 🏗️ 建议交付的文件
- [ ] 系统架构图（用 draw.io / Excalidraw 绘制，导出 PNG + 源文件）
- [ ] 核心业务流程图（订单状态机、审批流等关键流程）
- [ ] 已知问题清单（记录遗留的技术债和已知 Bug，注明风险等级）
- [ ] 后续优化建议（给客户或下一任开发者的改进方向）
- [ ] 技术选型说明（为什么选这个框架/数据库，方便后续维护者理解）
```

### 2.2 账号安全移交规范

```
⚠️ 账号移交安全原则：

1. 禁止明文邮件发送密码 → 使用加密工具（1Password、Bitwarden 分享链接）
2. 移交后立即修改密码 → 确认客户接收后，让客户自行修改为新密码
3. 敏感信息不进代码库 → 检查 git log，确保历史提交中无密码/密钥
4. 移交清单存档 → 双方签字确认已接收所有账号

安全移交工具推荐：
- 1Password（企业版支持安全分享链接，查看一次后失效）
- Bitwarden（开源，支持 Send 功能）
- 加密 ZIP + 电话告知密码（分开传输）
```

## 三、功能验收检查清单

### 3.1 P0 必须通过（否则不能交付）

```markdown
## 功能验收清单

### 用户认证模块
- [ ] 用户注册（正常流程）
- [ ] 用户注册（错误处理：重复邮箱、密码格式不符）
- [ ] 用户登录（正常流程）
- [ ] 用户登录（错误处理：密码错误、账号不存在）
- [ ] Token 自动刷新（登录后长时间操作不会被强制下线）
- [ ] 退出登录（Token 失效）

### 核心业务功能（根据具体项目填写）
- [ ] [功能1]：正常流程 + 异常流程
- [ ] [功能2]：正常流程 + 异常流程
- [ ] ...

### 权限控制
- [ ] 未登录用户无法访问受保护页面
- [ ] 普通用户无法访问管理员功能
- [ ] 用户 A 无法操作用户 B 的数据

### 性能基准
- [ ] 首屏加载时间 < 3 秒（3G 网络）
- [ ] 核心 API 响应时间 P99 < 500ms
- [ ] 并发 50 用户下系统稳定运行

### 安全检查
- [ ] HTTPS 已启用，HTTP 自动跳转
- [ ] 密码以哈希形式存储（非明文）
- [ ] SQL 注入防护（可用 sqlmap 基础检测）
- [ ] XSS 防护（输出内容已转义）
```

### 3.2 验收流程

```
Step 1：开发者自测（上线前 2 天）
→ 按照验收清单逐项自测
→ 录制关键功能演示视频备份

Step 2：客户预验收（上线前 1 天）
→ 提供 staging 环境账号给客户
→ 客户自行体验，记录问题

Step 3：问题修复（上线前）
→ 修复 P0/P1 级问题
→ P2/P3 问题列入已知问题清单

Step 4：正式验收（生产上线当天）
→ 客户在生产环境完成验收
→ 双方签署验收确认单

Step 5：质保期开始（建议 1-3 个月）
→ 功能性 Bug 免费修复
→ 新增需求走变更单流程
```

## 四、运维培训大纲

### 4.1 培训内容（1-2 小时视频会议）

```markdown
## 运维培训议程

### Part 1：系统架构概览（15 分钟）
- 整体架构介绍（服务器、数据库、CDN）
- 各组件之间的关系
- 数据流向说明

### Part 2：日常运维操作（30 分钟）
- 如何查看服务状态
- 如何查看日志（错误排查方法）
- 如何重启服务
- 如何备份数据库
- 如何更新前端静态资源

### Part 3：常见问题处理（20 分钟）
- 服务不可用时的排查步骤
- 磁盘空间不足的处理
- 数据库连接超时的处理

### Part 4：紧急联系方式（5 分钟）
- 开发者联系方式（质保期内）
- 云服务商客服
- 域名服务商客服

### Part 5：Q&A（15 分钟）
```
