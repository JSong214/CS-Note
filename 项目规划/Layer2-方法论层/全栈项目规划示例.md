# 全栈项目规划示例



## 初始阶段

### 带着约束搭地基

在这个阶段，我们的目标不是写业务逻辑，而是搭建好能够支持“切片开发”的最小环境。我们需要让 AI 建立前后端仓库，并跑通一个最简单的“Hello World”接口。

**Vibe Coding 技巧融入**：在这个阶段，我们要向 AI 明确“防御性编程”的基调。

**你可以向 AI 发送的第一条指令（Prompt）：**

> “我们要从 0 开始构建一个全栈项目。我已经向你提供了 `@全局开发约束与架构(rules).md` 和 `@全栈项目规划：垂直切片与 API 先行.md`。
>
> 现在我们要执行‘第0阶段：地基搭建’。请帮我初始化前后端项目（前端用 React+Vite，后端用 Node.js+Express，或其他你偏好的技术栈）。 **要求：**
>
> 1. 只建立最基础的目录结构和数据库连接配置，设计最核心的 1-2 个实体（例如 User），不要过度设计。
> 2. 写一个 `GET /api/v1/health` 的 Hello World 接口。
> 3. **严格遵守规则**：这个简单的接口也必须被 `try/catch` 包裹，并且在 `catch` 块中打印包含上下文的底层日志。
>
> 请一步步引导我运行命令，确保前端能成功请求到这个健康检查接口。”

------



## 核心阶段 

### 步骤 1 - 切片定义与 API 契约设计

当地基搭好后，我们就进入了日常的迭代循环。根据规则，在编写任何前后端业务逻辑代码之前，必须先定义 API 契约。

**Vibe Coding 技巧融入**：这里我们要使用之前学过的**“苏格拉底提问法（元提示）”**。不要让 AI 直接生成接口文档，先让它结合业务找漏洞。

假设我们挑选的第一个垂直切片功能是**“用户注册（包含密码哈希和初始状态分配）”**。

**你可以向 AI 发送的第二条指令（Prompt）：**

> “地基搭建完毕。现在我们进入核心阶段，挑选的第一个垂直切片是：**用户注册功能**。
>
> 根据全局规则，我们必须‘API 契约先行’。这份契约需要包含数据模型、路由、Request/Response JSON 结构和错误码。
>
> 但在我正式让你输出这份 API 契约之前，为了贯彻‘防御性编程与悲观路径’的理念，请你扮演资深架构师： **向我提出 3 到 5 个关于此功能的边界条件或安全验证问题**（例如：邮箱格式的 Zod 校验规则、密码强度要求、如果数据库写入时发现邮箱已存在该返回什么错误码等）。
>
> 等我回答完这些问题，你再输出一份完美的 API 契约文档（例如 Swagger/OpenAPI 格式）。”

------



### 步骤 2：后端穿透 (Backend Slice)

#### 第一步：让 AI 搭骨架 (Stubbing)

根据规则，在实现具体逻辑前，必须先写出函数签名和控制流伪代码。

**你可以复制这段 Prompt 发给 AI：**

> “我们现在进行‘用户注册’切片的后端开发。技术栈是 Go。 假设我们已经有了 `POST /api/v1/register` 的路由定义。
>
> 请根据 `@全局开发约束与架构(rules).md` 中的‘先搭骨架’原则，为我编写 Controller 层（如 `RegisterUserHandler`）和 Service 层（如 `CreateUserService`）的**骨架代码**。
>
> **要求：**
>
> 1. **不要实现任何具体逻辑**（不要写真实的 SQL 或哈希算法）。
> 2. 只写出函数签名。
> 3. 在函数体内，用清晰的中文注释写出每一步的**控制流伪代码**。
> 4. 控制流必须包含：输入校验（不可信输入）、检查邮箱是否已存在、密码哈希处理、数据库写入事务。
>
> 请输出这两个函数的骨架。”

**预期效果：** AI 会给你一个非常清晰的 Go 代码骨架，里面全是 `// TODO:` 注释，清楚地展示了逻辑流向。这让你能在写代码前审查架构走向。



#### 第二步：填充细节与“悲观路径”防守

当你确认骨架的流向没问题后，我们让 AI 填肉。根据规则，必须强制处理异常分支，且记录详细的错误日志。

**你可以接着发送这段 Prompt：**

> “骨架逻辑确认无误。现在请填充 `RegisterUserHandler` 和 `CreateUserService` 的具体实现细节。
>
> 请严格遵守 `@全局开发约束与架构(rules).md` 中的‘防御性编程与悲观路径’规则：
>
> 1. **校验先行**：使用 Go 的校验库（如 `validator`）严格检查 email 格式和 password 强度，失败直接提前返回（Early Return） 400 错误。
> 2. **处理所有 `err`**：每一处可能出错的地方（查库、哈希、写库）都必须处理 `err != nil`。严禁忽略任何错误。
> 3. **底层日志与友好的上层响应**：当捕获到错误时（例如数据库连接超时），向客户端返回通用的 `500 内部服务器错误`，但**必须在控制台打印包含请求上下文（如试图注册的 email）的详细底层日志**。
>
> 请输出填充后的完整 Go 代码。”

**预期效果：** 这时 AI 产出的 Go 代码将极其健壮，不再是脆弱的“完美情况”代码。



#### 第三步：强制要求测试覆盖 (Contract & Sad Paths)

后端逻辑写完后，根据规则，必须为其编写自动化测试，且必须测试异常分支并 Mock 外部依赖。

**你可以发送这最后一段 Prompt 来收尾后端穿透：**

> “后端代码已完成。根据 `@全局开发约束与架构(rules).md` 的‘自动化测试与验证’规则，现在请为 `CreateUserService` 编写单元测试（使用 Go 的 testing 包和 testify）。
>
> **测试要求：**
>
> 1. **Mock 依赖**：必须 Mock 掉 UserRepository（数据库操作），我们只测试 Service 层的控制流。
> 2. **强制测试悲观路径**：不要只写注册成功的 Happy Path 测试。你**必须**为以下情况编写独立的测试用例：
>    - 邮箱已存在（Mock DB 返回已有记录），断言返回 `ErrEmailAlreadyExists`。
>    - 密码哈希失败（Mock 哈希组件抛错），断言返回内部错误。
>    - 数据库写入超时或失败（Mock DB 写入报错），断言返回正确的上层错误封装。
>
> 请输出测试文件代码。”

-----



### **步骤 3：前端穿透 (Frontend Slice)**

#### 第一步：构建前端状态机与表单 UI 骨架

不要让 AI 上来就写 `axios.post`。我们要先让它把前端的“状态容器”和防守逻辑（表单校验）搭好。

**你可以向 AI 发送这段 Prompt：**

> “后端 `POST /api/v1/register` 接口已经就绪。现在我们要进行‘用户注册’切片的前端穿透。技术栈是 Vue 3 (Composition API)。
>
> 请根据 `@全局开发约束与架构(rules).md`，为我编写一个 `RegisterForm.vue` 组件的**骨架与状态管理逻辑**。
>
> **要求：**
>
> 1. **状态闭环**：必须使用 `ref` 或 `reactive` 显式定义 3 个核心异步状态：`isLoading`（布尔值）、`successMessage`（字符串）、`errorMessage`（字符串）。
> 2. **防御性编程**：在前端就拦截非法输入。请引入前端校验逻辑（可以手写正则或使用 Vue 相关的校验库），在用户点击提交时，如果邮箱或密码格式不合法，直接在输入框下方显示红色错误提示，**阻止发起网络请求**。
> 3. **UI 骨架**：写出包含 Email、Password 输入框和 Submit 按钮的 template。当 `isLoading` 为 true 时，按钮必须变为‘注册中...’并禁用（disabled）。
>
> 先不要写具体的 API 请求代码，用 `// TODO: 调用真实注册接口` 代替。请输出这个 Vue 组件。”

**预期效果：** AI 会给你一个状态极其严密、带有前端前置校验的干净组件。即使用户疯狂点击“注册”，只要处于 Loading 状态或者格式不对，都不会对后端造成压力。




#### 第二步：直连真实 API，处理“悲观路径” UI 映射

骨架打好后，我们要把刚刚用 Go 写的真实接口接进来。

**你可以接着发送这段 Prompt：**

> “Vue 组件的状态骨架非常好。现在请替换掉 `// TODO` 注释，完成真实的 API 对接。
>
> 请严格遵守 `@全局开发约束与架构(rules).md` 中的以下规则：
>
> 1. **即时集成（零 Mock）**：不要写任何 Mock 逻辑，直接使用 `fetch` 或 `axios` 调用真正的 `http://localhost:8080/api/v1/register`（假设我们的 Go 后端跑在这里）。
> 2. **强制异常分支处理**：必须用 `try/catch` 包裹请求。
>    - 在 `try` 的最后，必须将 `isLoading` 设为 false，清空 `errorMessage`，设置 `successMessage`（例如：‘注册成功，请登录！’），并清空表单。
>    - 在 `catch` 中，必须将 `isLoading` 设为 false。根据后端返回的 HTTP 状态码（比如我们在 Go 里写的 400 邮箱已存在，或 500 内部错误），将具体的错误信息赋值给 `errorMessage`，并通过 UI Toast 或红色警示框展示给用户。
>
> 请输出补全 API 请求逻辑后的完整 `RegisterForm.vue` 代码。”

**预期效果：** AI 会生成一个极其成熟的组件。它能优雅地处理网络延迟（Loading）、后端报错（展示友好的错误信息，而不是控制台一片红），以及成功后的状态重置。

------



### 步骤 4：即时集成与验证 (Integrate & Verify)

根据《全栈项目规划》文档，部署与验证不是最后的大爆炸，而是日常习惯。

你要做的动作是：

1. **启动 Go 后端**。
2. **启动 Vue 前端**。
3. **在浏览器中真实操作一遍**：
   - 测试**悲观路径**：输入错误格式的邮箱、输入已经注册过的邮箱、甚至关掉 Go 后端模拟网络断开，看看前端的 Error 状态和提示是否按预期工作。
   - 测试**Happy Path**：输入正确信息，点击注册，观察 Loading 状态，看到 Success 提示，去数据库检查数据是否真的进去了。
