# 数据库设计规范

> **文档定位**：Layer 3 — 规范层（日常开发参考）
> **适用技术栈**：PostgreSQL（主要）/ MySQL（兼容参考）
> **核心原则**：数据库变更必须可回滚，通过 Migration 管理，绝不手动改表

---

## 一、通用字段约定

### 1.1 所有表必须包含的标准字段

```sql
-- 每张业务表的标准字段（不可省略）
CREATE TABLE example (
    id         BIGSERIAL    PRIMARY KEY,                           -- 主键，自增大整数
    created_at TIMESTAMPTZ  NOT NULL DEFAULT NOW(),                -- 创建时间（含时区）
    updated_at TIMESTAMPTZ  NOT NULL DEFAULT NOW(),                -- 更新时间（含时区）
    deleted_at TIMESTAMPTZ  NULL                                   -- 软删除时间，NULL 表示未删除
);

-- 说明：
-- BIGSERIAL：等价于 BIGINT + AUTO_INCREMENT，支持 20+ 亿行
-- TIMESTAMPTZ：PostgreSQL 推荐，含时区信息，避免夏令时问题
-- 软删除（Soft Delete）：deleted_at IS NULL 表示有效数据
--   优点：数据可恢复、可审计
--   查询时必须加 WHERE deleted_at IS NULL 过滤
```

### 1.2 特殊场景的可选字段

```sql
-- 需要记录操作人时
created_by BIGINT   REFERENCES users(id),   -- 创建人
updated_by BIGINT   REFERENCES users(id),   -- 最后修改人

-- 需要乐观锁时（防止并发更新冲突）
version    INTEGER  NOT NULL DEFAULT 0,      -- 每次更新 +1

-- 需要逻辑排序时
sort_order INTEGER  NOT NULL DEFAULT 0,      -- 越小越靠前

-- 需要状态机时（推荐用枚举或 SMALLINT）
status     SMALLINT NOT NULL DEFAULT 0,      -- 0=草稿, 1=生效, 2=停用
```

## 二、命名规范

### 2.1 表名规范

```sql
-- ✅ 正确：小写蛇形，复数名词
users               -- 用户表
orders              -- 订单表
order_items         -- 订单明细表（多词用 _ 连接）
user_role_mappings  -- 多对多关联表

-- ❌ 错误
User                -- 驼峰命名
userOrder           -- 驼峰命名
user_order_item     -- 单数（推荐复数）
t_users             -- 带 t_ 前缀（无意义）
```

### 2.2 列名规范

```sql
-- ✅ 正确：小写蛇形，语义明确
user_id             -- 外键：关联表_id
phone_number        -- 多词连接
is_active           -- 布尔型：is_ 前缀
has_avatar          -- 布尔型：has_ 前缀
total_amount        -- 金额
status              -- 状态
retry_count         -- 计数器

-- ❌ 错误
userId              -- 驼峰
phone               -- 过于简短（可能歧义）
active              -- 不明确是布尔型
```

### 2.3 索引命名规范

```sql
-- 格式：idx_<表名>_<列名(s)>
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_orders_user_id_status ON orders(user_id, status);

-- 唯一索引：uq_<表名>_<列名(s)>
CREATE UNIQUE INDEX uq_users_email ON users(email);

-- 外键索引（通常自动创建）：fk_<表名>_<引用表名>
```

## 三、字段类型选择指南

### 3.1 常用字段类型

| 场景 | 推荐类型 | 说明 |
|---|---|---|
| 主键 | `BIGSERIAL` | 自增大整数，支持高并发 |
| 外键 | `BIGINT NOT NULL` | 引用其他表的 id |
| 短文本（<255字符） | `VARCHAR(n)` | 明确指定最大长度 |
| 长文本（文章内容等） | `TEXT` | 无长度限制 |
| 枚举状态 | `SMALLINT` | 配合应用层枚举，避免 ENUM 类型 |
| 布尔值 | `BOOLEAN` | true/false |
| 整数计数 | `INTEGER` | 通常够用 |
| 大整数 | `BIGINT` | 超过 21 亿时用 |
| 金额/价格 | `NUMERIC(19,4)` | 精确小数，绝不用 FLOAT |
| 时间 | `TIMESTAMPTZ` | 含时区，PostgreSQL 推荐 |
| 仅日期 | `DATE` | 不含时间的日期 |
| JSON 数据 | `JSONB` | PostgreSQL 的二进制 JSON，支持索引 |
| IP 地址 | `INET` | PostgreSQL 原生 IP 类型 |
| UUID | `UUID` | 需要分布式 ID 时 |

### 3.2 金额处理（重要）

```sql
-- ✅ 正确：用 NUMERIC 存储，单位为元
price       NUMERIC(19, 4) NOT NULL DEFAULT 0,   -- 精确到 4 位小数
total_amount NUMERIC(19, 4) NOT NULL DEFAULT 0,

-- ✅ 替代方案：存储分（整数），避免小数运算误差
-- price_cents INTEGER NOT NULL DEFAULT 0,        -- 单位：分（× 100）

-- ❌ 危险：永远不要用浮点数存储金额
-- price FLOAT,    -- 浮点数有精度损失！
-- price DOUBLE,   -- 同上
```

## 四、索引设计规范

### 4.1 必须建索引的场景

```sql
-- 1. 外键字段（防止关联查询全表扫描）
CREATE INDEX idx_orders_user_id ON orders(user_id);

-- 2. 高频查询的 WHERE 条件字段
CREATE INDEX idx_orders_status ON orders(status);

-- 3. 高频排序字段
CREATE INDEX idx_articles_created_at ON articles(created_at DESC);

-- 4. 唯一约束字段
CREATE UNIQUE INDEX uq_users_email ON users(email);
CREATE UNIQUE INDEX uq_users_phone ON users(phone_number);

-- 5. 复合查询（注意列顺序：选择性高的列放前面）
-- 常见查询：WHERE user_id = ? AND status = ?
CREATE INDEX idx_orders_user_id_status ON orders(user_id, status);
```

### 4.2 索引设计注意事项

```markdown
✅ 最佳实践：
- 软删除场景加过滤索引：WHERE deleted_at IS NULL
- 枚举字段选择性低（如 status 只有 3 个值），单独建索引效果差
  → 应与高选择性字段组成复合索引

❌ 常见错误：
- 在每个字段上都建索引（索引过多影响写性能）
- 复合索引列顺序错误（最左前缀原则）
- 在频繁更新的字段上建不必要的索引
```

```sql
-- 软删除过滤索引示例（PostgreSQL）
CREATE INDEX idx_users_email_active
ON users(email)
WHERE deleted_at IS NULL;

-- 这样查询 WHERE email = ? AND deleted_at IS NULL 会使用此索引
```

## 五、数据库迁移规范（Migration）

### 5.1 核心原则

```
❌ 禁止：直接登录数据库执行 ALTER TABLE（无法追溯、无法回滚）
✅ 必须：所有 schema 变更通过 Migration 文件管理
✅ 必须：每个 Migration 都有对应的 down 文件（可回滚）
✅ 必须：Migration 通过 CI/CD 自动执行（不依赖手动操作）
```

### 5.2 推荐工具：golang-migrate

```bash
# 安装
brew install golang-migrate  # macOS
# 或下载二进制：https://github.com/golang-migrate/migrate

# 项目目录结构
backend/
└── migrations/
    ├── 000001_create_users_table.up.sql
    ├── 000001_create_users_table.down.sql
    ├── 000002_add_avatar_to_users.up.sql
    ├── 000002_add_avatar_to_users.down.sql
    └── 000003_create_orders_table.up.sql
    └── 000003_create_orders_table.down.sql
```

```bash
# 创建新 Migration
migrate create -ext sql -dir migrations -seq create_users_table

# 执行升级（up）
migrate -path ./migrations -database "postgres://user:pass@localhost/mydb?sslmode=disable" up

# 回滚最近 1 次（down）
migrate -path ./migrations -database "postgres://..." down 1

# 查看当前版本
migrate -path ./migrations -database "postgres://..." version
```

### 5.3 Migration 文件规范

```sql
-- 000001_create_users_table.up.sql

CREATE TABLE users (
    id          BIGSERIAL    PRIMARY KEY,
    email       VARCHAR(255) NOT NULL,
    password    VARCHAR(255) NOT NULL,    -- bcrypt 哈希值
    nickname    VARCHAR(100) NOT NULL DEFAULT '',
    avatar_url  TEXT,
    status      SMALLINT     NOT NULL DEFAULT 1,  -- 1=正常, 2=封禁
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ
);

-- 索引
CREATE UNIQUE INDEX uq_users_email ON users(email) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_status ON users(status) WHERE deleted_at IS NULL;

-- 注释（可选但推荐）
COMMENT ON TABLE users IS '用户表';
COMMENT ON COLUMN users.status IS '用户状态：1=正常, 2=封禁, 3=注销';
```

```sql
-- 000001_create_users_table.down.sql

DROP TABLE IF EXISTS users;
```

```sql
-- 000002_add_avatar_to_users.up.sql（增加字段示例）

ALTER TABLE users ADD COLUMN IF NOT EXISTS phone_number VARCHAR(20);
CREATE UNIQUE INDEX uq_users_phone ON users(phone_number) WHERE deleted_at IS NULL;
```

```sql
-- 000002_add_avatar_to_users.down.sql

DROP INDEX IF EXISTS uq_users_phone;
ALTER TABLE users DROP COLUMN IF EXISTS phone_number;
```

### 5.4 Makefile 集成

```makefile
DB_URL ?= postgres://dev:dev_password@localhost:5432/myapp_dev?sslmode=disable

migrate:           ## 执行所有待执行的 Migration
	migrate -path ./migrations -database "$(DB_URL)" up

migrate-down:      ## 回滚最近一次 Migration
	migrate -path ./migrations -database "$(DB_URL)" down 1

migrate-version:   ## 查看当前 Migration 版本
	migrate -path ./migrations -database "$(DB_URL)" version

migrate-create:    ## 创建新 Migration 文件，用法：make migrate-create NAME=create_xxx_table
	migrate create -ext sql -dir migrations -seq $(NAME)
```

## 六、常见设计模式

### 6.1 软删除查询模式

```go
// GORM 示例：软删除模型
type BaseModel struct {
    ID        uint           `gorm:"primarykey"`
    CreatedAt time.Time
    UpdatedAt time.Time
    DeletedAt gorm.DeletedAt `gorm:"index"`  // GORM 原生支持软删除
}

// GORM 自动在查询时添加 WHERE deleted_at IS NULL
db.Find(&users)
// 等价于：SELECT * FROM users WHERE deleted_at IS NULL

// 查询包含已删除的数据
db.Unscoped().Find(&users)
// 等价于：SELECT * FROM users
```

### 6.2 多对多关联表设计

```sql
-- 用户-角色 多对多关联表
CREATE TABLE user_roles (
    id         BIGSERIAL    PRIMARY KEY,
    user_id    BIGINT       NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    role_id    BIGINT       NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ  NOT NULL DEFAULT NOW(),

    -- 联合唯一约束：防止重复关联
    CONSTRAINT uq_user_roles UNIQUE (user_id, role_id)
);

CREATE INDEX idx_user_roles_user_id ON user_roles(user_id);
CREATE INDEX idx_user_roles_role_id ON user_roles(role_id);
```

### 6.3 状态机设计（推荐使用 SMALLINT + 注释）

```sql
-- 订单状态
-- 0=待支付, 1=已支付, 2=已发货, 3=已收货, 4=已取消, 5=已退款
status SMALLINT NOT NULL DEFAULT 0;

COMMENT ON COLUMN orders.status IS '订单状态: 0=待支付, 1=已支付, 2=已发货, 3=已收货, 4=已取消, 5=已退款';
```

```go
// Go 应用层枚举定义
type OrderStatus int16

const (
    OrderStatusPending   OrderStatus = 0  // 待支付
    OrderStatusPaid      OrderStatus = 1  // 已支付
    OrderStatusShipped   OrderStatus = 2  // 已发货
    OrderStatusReceived  OrderStatus = 3  // 已收货
    OrderStatusCancelled OrderStatus = 4  // 已取消
    OrderStatusRefunded  OrderStatus = 5  // 已退款
)
```

## 七、数据库设计检查清单

```markdown
## 表设计自查清单

基础字段
- [ ] 包含 id, created_at, updated_at, deleted_at 四个标准字段
- [ ] 金额字段使用 NUMERIC(19,4)，未使用 FLOAT/DOUBLE
- [ ] 时间字段使用 TIMESTAMPTZ（含时区）

命名规范
- [ ] 表名为复数小写蛇形命名
- [ ] 列名为小写蛇形命名，语义明确
- [ ] 外键列名遵循 <引用表单数>_id 规范

索引设计
- [ ] 外键字段已建索引
- [ ] 高频查询 WHERE 字段已建索引
- [ ] 唯一约束已添加（邮箱、手机号等）
- [ ] 软删除过滤已加入索引 WHERE 条件

Migration
- [ ] 每个变更都有对应的 .up.sql 和 .down.sql
- [ ] Migration 文件序号连续，不重复
- [ ] down 文件可以完整回滚 up 文件的变更
- [ ] 重要字段已添加注释（COMMENT ON COLUMN）
```
