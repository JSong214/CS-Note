## 一、身份认证安全（Authentication）

### 1.1 JWT 标准实践

```go
// ✅ 正确：双 Token 机制（短生命期 Access Token + 可吊销 Refresh Token）
AccessToken  有效期：15 分钟（只用于接口鉴权，不可续期）
RefreshToken 有效期：7 天（存储在 Redis，使用后立即失效 → 单次使用）

// ✅ 正确：RefreshToken 轮换（每次刷新生成新 Token，旧的立即废弃）
// 好处：检测 Token 泄露（旧 Token 被使用 → 说明有人偷用 → 强制全量退出）

// ❌ 错误：
// - Token 永不过期
// - Token 有效期 30 天以上
// - RefreshToken 可重复使用（无旋转机制）
```

### 1.2 密码存储规范

```go
// ✅ 正确：bcrypt 哈希（推荐 cost=12）
import "golang.org/x/crypto/bcrypt"

// 存储密码
hashedPassword, err := bcrypt.GenerateFromPassword([]byte(password), 12)

// 验证密码
err := bcrypt.CompareHashAndPassword([]byte(hashedPassword), []byte(inputPassword))

// ❌ 错误（以下均禁止）：
// - 明文存储密码
// - MD5/SHA1 哈希（可被彩虹表破解）
// - 无盐哈希
// - 对称加密（可解密）
```

### 1.3 前端 Token 存储规范

```typescript
// ❌ 危险：localStorage（XSS 攻击可以直接读走）
localStorage.setItem('token', accessToken)  // 禁止！

// ❌ 危险：sessionStorage（同上，XSS 可读）
sessionStorage.setItem('token', accessToken)  // 禁止！

// ✅ 方案 A：内存存储（最安全，刷新会丢失）
// 配合 Refresh Token 自动续期机制
let accessToken: string | null = null

const tokenManager = {
  set(token: string) { accessToken = token },
  get() { return accessToken },
  clear() { accessToken = null }
}

// ✅ 方案 B：HttpOnly Cookie（推荐，JS 完全无法读取）
// 后端设置响应头（Go 示例）：
// http.SetCookie(w, &http.Cookie{
//   Name:     "refresh_token",
//   Value:    refreshToken,
//   HttpOnly: true,       // JS 无法读取
//   Secure:   true,       // 仅 HTTPS 传输
//   SameSite: http.SameSiteStrictMode,  // 防 CSRF
//   Path:     "/api/v1/auth/refresh",   // 限制路径
//   MaxAge:   7 * 24 * 3600,
// })
```

## 二、API 接口安全

### 2.1 每个接口上线前必查清单

```markdown
## API 安全检查（每个接口上线前必查）

### 认证与授权
- [ ] 需要登录的接口是否挂载了 Auth 中间件（无一例外）
- [ ] 管理员接口是否有额外的角色校验
- [ ] 分页接口是否有 pageSize 上限（防止 limit=99999）
  → 建议：pageSize 最大 100，超出则返回 400

### 数据访问控制（IDOR 防护）
- [ ] 操作资源前是否校验了当前用户对该资源的所有权
  → 示例：DELETE /api/orders/:id → 必须校验 orders.user_id == currentUser.id
- [ ] 批量操作是否有权限校验（防止 A 删除 B 的数据）

### 输入校验
- [ ] 所有用户输入是否经过参数校验（长度、格式、范围）
- [ ] 文件上传是否校验了文件类型（MIME type，而非文件名后缀）
- [ ] 文件上传是否限制了文件大小
- [ ] 富文本内容是否经过 XSS 过滤

### 输出安全
- [ ] 密码字段是否已从响应中移除
- [ ] 手机号等敏感字段是否脱敏（如：138****8888）
- [ ] 错误信息是否泄露了内部实现细节（如：SQL 错误语句）

### 限流防护
- [ ] 登录/注册接口是否有限流（同 IP 1 分钟最多 5 次）
- [ ] 短信/邮件发送接口是否有限流（防止短信轰炸）
- [ ] 高成本接口（AI 调用、文件生成）是否有限流
```

### 2.2 CORS 配置规范

```go
// ✅ 正确：明确白名单（生产环境）
allowedOrigins := []string{
    "https://yourdomain.com",
    "https://www.yourdomain.com",
}

// ❌ 危险：
// Access-Control-Allow-Origin: *   // 允许任何域名，危险！
// Access-Control-Allow-Credentials: true + *  // 绝对禁止的组合

// Go Gin 示例
router.Use(cors.New(cors.Config{
    AllowOrigins:     allowedOrigins,
    AllowMethods:     []string{"GET", "POST", "PUT", "DELETE"},
    AllowHeaders:     []string{"Authorization", "Content-Type"},
    AllowCredentials: true,
    MaxAge:           12 * time.Hour,
}))
```

### 2.3 限流中间件实现

```go
// 使用 golang.org/x/time/rate 或 github.com/ulule/limiter

// 基于 IP 的限流（登录接口）
// 同一 IP，1 分钟内最多 5 次请求

// 使用 Redis 实现分布式限流（多实例部署时必须）
func RateLimitMiddleware(maxRequests int, window time.Duration) gin.HandlerFunc {
    return func(c *gin.Context) {
        key := fmt.Sprintf("rate_limit:%s:%s", c.ClientIP(), c.FullPath())

        // Redis INCR + EXPIRE 原子操作
        count, err := redis.Incr(ctx, key).Result()
        if count == 1 {
            redis.Expire(ctx, key, window)
        }

        if count > int64(maxRequests) {
            c.JSON(http.StatusTooManyRequests, gin.H{
                "code": 429,
                "message": "请求过于频繁，请稍后再试",
            })
            c.Abort()
            return
        }
        c.Next()
    }
}

// 登录接口应用：1分钟内最多 5 次
router.POST("/api/v1/auth/login", RateLimitMiddleware(5, time.Minute), authHandler.Login)
```

## 三、SQL 注入防护

### 3.1 规范

```go
// ✅ 正确：参数化查询（GORM 和 sqlx 默认保障）

// GORM 示例
db.Where("email = ?", email).First(&user)                // ✅ 安全
db.Where("email = ? AND status = ?", email, 1).Find()   // ✅ 安全

// sqlx 示例
db.Get(&user, "SELECT * FROM users WHERE email = $1", email)  // ✅ 安全

// ❌ 危险：字符串拼接（绝对禁止）
query := "SELECT * FROM users WHERE email = '" + email + "'"  // ❌ SQL 注入漏洞
db.Raw(query).Scan(&user)                                       // ❌ 禁止

// ❌ 危险：fmt.Sprintf 拼接 SQL
db.Raw(fmt.Sprintf("SELECT * FROM users WHERE id = %s", id))   // ❌ 禁止
```

## 四、XSS 防护

### 4.1 前端防护

```typescript
// ✅ Vue 3 默认对 {{ }} 插值进行转义，基础防护已有
// 但以下情况需要额外注意：

// ❌ 危险：v-html 使用用户输入（XSS 高危）
<div v-html="userInput"></div>  // 危险！

// ✅ 正确：使用 DOMPurify 净化后再使用
import DOMPurify from 'dompurify'
const safeHTML = DOMPurify.sanitize(userInput)
// <div v-html="safeHTML"></div>

// ✅ 用 innerText 代替 innerHTML
element.innerText = userInput  // 安全（自动转义）
element.innerHTML = userInput  // 危险（不转义）
```

### 4.2 后端防护（富文本存储）

```go
// 存储用户提交的富文本（如文章内容）前，必须过滤危险标签
// 推荐库：github.com/microcosm-cc/bluemonday

import "github.com/microcosm-cc/bluemonday"

// 仅允许安全的 HTML 标签（博客文章场景）
p := bluemonday.UGCPolicy()
sanitizedHTML := p.Sanitize(userInputHTML)

// 完全禁止 HTML（纯文本评论场景）
p := bluemonday.StrictPolicy()
sanitizedText := p.Sanitize(userInputHTML)
```

## 五、敏感数据保护

### 5.1 日志中的敏感信息

```go
// ❌ 危险：日志中打印敏感字段
log.Info("用户登录", "email", email, "password", password)   // 密码进日志！禁止！
log.Info("用户注册", "phone", phone)                          // 手机号进日志，不建议

// ✅ 正确：脱敏后记录
log.Info("用户登录成功", "email", maskEmail(email), "user_id", userID)
log.Info("发送短信", "phone", maskPhone(phone))

// 脱敏函数示例
func maskEmail(email string) string {
    // test@example.com → te**@example.com
    parts := strings.Split(email, "@")
    if len(parts) != 2 || len(parts[0]) <= 2 {
        return "***@" + parts[1]
    }
    return parts[0][:2] + "**@" + parts[1]
}

func maskPhone(phone string) string {
    // 13812345678 → 138****5678
    if len(phone) != 11 { return "***" }
    return phone[:3] + "****" + phone[7:]
}
```

### 5.2 API 响应中的敏感字段

```go
// ✅ 正确：明确标记不输出的字段（GORM + JSON tag）
type User struct {
    ID        uint   `json:"id"`
    Email     string `json:"email"`
    Password  string `json:"-"`         // ✅ 永远不输出到 JSON
    Phone     string `json:"phone_masked"` // 脱敏后输出

    // 或者使用独立的 Response DTO（推荐）
}

// ✅ 最佳实践：使用独立的响应 DTO，而不是直接返回 DB 模型
type UserResponse struct {
    ID       uint   `json:"id"`
    Email    string `json:"email"`
    Nickname string `json:"nickname"`
    // 注意：没有 Password 字段
}
```

## 六、HTTPS 与传输安全

### 6.1 HTTPS 必须配置项

```nginx
# ✅ 正确的 SSL 配置（Nginx）
server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # 安全响应头（必须配置）
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;           # 防点击劫持
    add_header X-Content-Type-Options "nosniff" always;       # 防 MIME 嗅探
    add_header X-XSS-Protection "1; mode=block" always;       # 旧版浏览器 XSS 防护
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
}

# HTTP 强制跳转 HTTPS
server {
    listen 80;
    server_name yourdomain.com;
    return 301 https://$host$request_uri;
}
```

## 八、安全事件响应快速参考

| 安全事件 | 立即操作 | 后续处理 |
|---|---|---|
| Token 泄露 | 强制吊销所有 RefreshToken（清空 Redis） | 通知受影响用户修改密码 |
| SQL 注入攻击 | 检查日志确认攻击范围，封禁攻击 IP | 修复漏洞，评估数据泄露范围 |
| 暴力破解登录 | 触发自动封禁（限流已覆盖），手动封禁异常 IP | 检查是否有账号被攻破 |
| 服务器 Root 权限泄露 | 立即下线服务器，切换备用 | 全量修改所有密码密钥，安全审计 |
| DDoS 攻击 | 启用云服务商 DDoS 防护，切换到高防 IP | 分析攻击来源，添加封禁规则 |
